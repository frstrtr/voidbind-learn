难度调整

比特币、莱特币、狗狗币和 c2pool 份额链如何设定各自的难度

2026 年 11 月更新。本页第一版称比特币的难度重定使用“区块 mediantime”，并且是把难度乘以时间跨度比值。两点都是错的：难度重定使用的是区块时间戳，而按比值缩放的是目标值，因此难度朝相反方向变化。本页已依据 Bitcoin Core 源代码重写，并新增了关于莱特币、狗狗币和 c2pool 份额链的章节。

比特币的难度重定

比特币每 2016 个区块设定一个新的目标值，使区块保持大约每 10 分钟产生一个（14 天产生 2016 个区块，即目标时间跨度 T = 1,209,600 s）。步骤如下，与 Bitcoin Core 的 src/pow.cpp 一致：

  1. 测量。实际时间跨度等于本周期最后一个区块的时间戳（nTime）减去本周期第一个区块（即 2015 个区块之前的那个区块）的时间戳。这里用的是区块自身区块头中的时间戳，而不是它们的过去中位时间（MTP）。
  2. 限幅。实际时间跨度被限制在 [T/4, 4T] 范围内，因此一次难度重定最多让目标值朝任一方向变化 4 倍。
  3. 缩放目标值。新目标值 = 旧目标值 × 实际时间跨度 / T。区块来得太快，比值就小于 1，目标值变小，难度变高。
  4. 封顶并编码。新目标值不得超过该链允许的最大目标值（即“难度 1”目标值，对应最低难度），并以紧凑的 nBits 形式写入后续区块头，这会对它做轻微的舍入。

难度等于难度 1 目标值除以当前目标值，因此难度按时间跨度比值的倒数变化。

TARGET_TIMESPAN = 14 * 24 * 60 * 60      # 2016 blocks x 10 minutes
POW_LIMIT = 0xffff << 208                 # difficulty-1 target (nBits 0x1d00ffff)

def bits_to_target(bits):
    exponent, mantissa = bits >> 24, bits & 0x007fffff
    return mantissa << (8 * (exponent - 3)) if exponent >= 3 else mantissa >> (8 * (3 - exponent))

def next_target(last_bits, last_time, first_time):
    """last_time: nTime of the last block of the period.
    first_time: nTime of the block 2015 blocks before it."""
    actual = last_time - first_time
    actual = max(TARGET_TIMESPAN // 4, min(actual, TARGET_TIMESPAN * 4))
    new = bits_to_target(last_bits) * actual // TARGET_TIMESPAN
    return min(new, POW_LIMIT)

def difficulty(target):
    return POW_LIMIT / target

随后 Bitcoin Core 把结果重新编码为 nBits（GetCompact），保留三个字节的尾数。窗口覆盖的是 2015 个间隔而不是 2016 个，这是第一个版本就存在的一个著名的差一错误，如今已成为共识规则。示例：用区块 30,240 和 32,255 的时间戳，该函数为高度 32,256 给出 nBits = 0x1d00d86a，这是比特币的第一次难度上调（难度约为 1.18）。

过去中位时间

一个区块的过去中位时间（MTP）是该区块及其之前十个区块的时间戳的中位数。它由每个节点自行计算，并不是区块头中的字段。它不受单个错误或被操纵的时间戳影响，比特币把它用于两条规则：

  • 新区块的时间戳必须晚于其父区块的 MTP（否则报“time-too-old”）；
  • 基于时间的锁定时间与 MTP 比较，而不是与区块自身的时间戳比较（BIP 113）。

它不参与难度重定。下面是原页面的示例，通过 RPC 计算链顶端区块的 MTP（Bitcoin Core 的 getblock 也会直接以 mediantime 返回它）：

import bitcoin.rpc
 def calculate_mediantime():
    proxy = bitcoin.rpc.Proxy()  # Establish connection to Bitcoin Core client
    block_count = proxy.getblockcount()
    if block_count >= 11:
        timestamps = []
        for height in range(block_count, block_count - 11, -1):
            block_hash = proxy.getblockhash(height)
            block = proxy.getblock(block_hash)
            timestamp = block['time']
            timestamps.append(timestamp)
        sorted_timestamps = sorted(timestamps)
        mediantime = sorted_timestamps[5]  # Take the middle timestamp
        return mediantime
    return None  # Return None if there are not enough blocks to calculate mediantime
 # Example usage
 mediantime = calculate_mediantime()
 print(mediantime)

在上面的代码片段中，我们使用 bitcoin.rpc.Proxy 类连接到正在运行的 Bitcoin Core 客户端。calculate_mediantime 函数首先用 getblockcount 获取当前区块数。如果区块链中至少有 11 个区块，就继续计算。它从当前区块开始，遍历之前的 11 个区块，并用 getblock 获取区块时间戳。这些时间戳存放在 timestamps 列表中。接着用 sorted 函数把 timestamps 列表按升序排序。最后，取排序后列表中间的时间戳（索引 5）作为 mediantime，由函数返回。如果区块数不足以计算 mediantime，则返回 None。

莱特币

莱特币沿用比特币的规则，出块间隔为 2.5 分钟：3.5 天产生 2016 个区块。有一处不同：从第二个周期起，窗口回溯完整的 2016 个区块而不是 2015 个（这一修复归功于 Art Forz，用于防范难度操纵）。c2pool 的内置莱特币节点根据它已同步的区块头自行计算下一个目标值，使用相同的限幅和相同的时间戳。

狗狗币

狗狗币由 c2pool 与莱特币联合挖矿。在高度 145,000 之前，它的难度重定窗口为 4 小时（240 个一分钟区块）。从该高度起，它使用 DigiShield，每个区块都进行难度重定。联合挖矿（AuxPoW）从高度 371,337 开始。c2pool 的内置狗狗币节点遵循这两套规则。

份额链自身的难度

P2Pool 份额链有它自己的难度，按份额逐个设定，而不是按周期设定。在 c2pool 中（与 p2pool 相同）：

  • 节点根据最近的份额估算矿池的算力，并计算出能使每个份额周期产生一个份额的目标值：莱特币份额链为 15 秒，比特币为 30 秒；
  • 结果被限制在前一个份额目标值的 ±10% 以内，因此份额难度平滑变化；
  • 当连续 20 个份额周期（莱特币上为 5 分钟）没有新份额到达时，紧急难度规则会放宽参考目标值：此后每再过 10 个份额周期，参考目标值翻一倍，中间按线性插值，然后再应用 ±10% 的限幅。这可以防止突然失去大部分算力的矿池停滞。
V37目标值与难度，以及绝对调度。

难度与目标值互为倒数（difficulty = max_target / target），因此难度重定把目标值乘以时间跨度比值，难度则朝相反方向变化：区块更快（比值更小）会提高难度。

在较长的窗口上沿链回溯来做难度重定，开销很大。绝对调度（ASERT 式）以常数时间直接根据一个锚定区块和最新区块计算目标值。它不遍历任何窗口，因此窗口内的时间戳无法使目标值漂移，不过最新区块自身的时间戳仍然有影响。比特币现金自 2020 年 11 月起就在使用这种调度。在 V37 设计工作中，它是份额链自身难度的候选方案；目前 c2pool 的份额链使用的是上面那种按份额调整的规则。
