c2pool 现状

c2pool 在 v0.2.12.16 版本（2026 年 11 月 25 日）时的状态

c2pool 是去中心化矿池 p2pool 的 C++ 重新实现，为 V36 份额格式而构建。它没有矿池运营者：矿工运行节点，这些节点就一条份额链达成一致，节点找到的每个区块都在该区块自己的 coinbase（coinbase 交易）中向矿工付款。源代码位于 github.com/frstrtr/c2pool。

链

c2pool 为每条父链构建一个二进制程序（c2pool-<coin>）。有几条父链还会在同一个 coinbase 中联合挖矿 AuxPoW 子链。

父链算法联合挖矿状态
莱特币（LTC）Scrypt狗狗币（内置节点）；PEP、LKY、SHIC 通过外部守护进程，未经测试；BELLS 和 JKC 尚未支持生产（V36 份额链，已挖出真实的莱特币和狗狗币区块）
达世币（DASH）X11无生产，无需守护进程
比特币（BTC）SHA-256dNamecoin，开发中运行中，无需守护进程
DigiByte（DGB）Scrypt狗狗币（内置）运行中，无需守护进程，仅主网
比特币现金（BCH）SHA-256d无运行中，无需守护进程
BIP-110（Bitcoin Knots 分叉）BLAKE2b（高度 961,640 之前为 SHA-256d）无实验性，无需守护进程
门罗币（XMR）RandomX无实验性，不在发布包中

“运行中”表示有一个公共 voidbind 节点在运行该二进制程序，并且服务路径上没有币种守护进程。这并不代表已达到生产成熟度：只有莱特币和达世币两条线处于生产使用中。DigiByte 以其 Scrypt 算法作为一条独立的父链运行；它不是莱特币的子链。

关于门罗币，项目自己的说法是：“Experimental (v37 lane, Path B payouts; c2pool-v37-xmr, can run daemonless; not built by the release workflow): regtest, stagenet and testnet run a pool; mainnet runs only --follow-only and needs --i-understand-mainnet even for that.”（译文：“实验性（v37 通道，Path B 支付；c2pool-v37-xmr，可以无需守护进程运行；不由发布工作流构建）：regtest、stagenet 和测试网可以运行矿池；主网只能运行 --follow-only，即便如此也需要 --i-understand-mainnet。”）主网矿池模式在代码中被禁用。（README，Supported chains）

无需币种守护进程

  • 莱特币和狗狗币。c2pool 为这两条链内置了轻量级节点。它们通过各币种自己的点对点网络同步区块头，维护一个 UTXO 集以计算手续费，维护内存池，并自行构建区块模板。不需要 litecoind 或 dogecoind。
  • 达世币。c2pool-dash 自己实现达世币点对点协议，并在节点内部重建确定性主节点列表、LLMQ 仲裁、ChainLocks 和 DIP-4 coinbase。它不需要 dashd、不需要 RPC 凭据，也不需要钱包访问权限。以这种方式构建的区块已被达世币主网接受。Dash Core 24 的规则从 v0.2.11.1 起内置，因此无需守护进程的矿池在这次硬分叉中没有需要升级的 dashd。节点仍然可以带一个 dashd 作为后备来启动。
  • 比特币、比特币现金、DigiByte 和 BIP-110 在公共 voidbind 节点上同样无需币种守护进程运行。

莱特币份额链

  • 自 2026-11-13 00:00:00 UTC 起，每个份额都是份额版本 3601 的份额：即份额类型 3601 下的 V36 份额格式，由版本中的固定激活日（flag day）确定，而不是通过投票。它改变了联合挖矿的支付规则，并允许一个份额同时携带多条联合挖矿链。
  • 只有 c2pool v0.2.12.1 及更高版本在这条份额链上。Python 版 p2pool 节点不在其上。
  • Python 实现 p2pool-merged-v36 和 p2pool-dash 已不再维护。所有更新，包括安全修复，都只在 c2pool 中发布。
  • 支付采用带指数衰减的 PPLNS（按最近 N 份额支付），半衰期为窗口（8,640 个份额）的四分之一。目标是每 15 秒产生一个份额。

公共节点

公共 voidbind 节点及其仪表板：ltc.voidbind.com（莱特币 + 狗狗币）、dash.voidbind.com、btc.voidbind.com、bch.voidbind.com、dgb.voidbind.com 和 bip110.voidbind.com。每个仪表板都是该节点份额链的一个视图；任何运行节点的人都能从自己的副本中看到相同的数据。

下载与校验

  • 每条父链的安装包都在版本发布页面上，提供 Linux x86_64（.tar.gz）、Windows x86_64（.zip 或安装程序）和 macOS（一个同时支持 Apple Silicon 和 Intel 的通用包，需 macOS 26.0 或更高版本）。
  • 每个版本都附带一个 SHA256SUMS 文件，从 v0.2.7 起还附带分离式签名 SHA256SUMS.asc。签名密钥发布在 github.com/frstrtr.gpg，指纹为 99556F8DE6AD66057A1A10EC50AB1379285EFE76。
  • 已知问题列在 KNOWN_ISSUES.md 中。

下一步

V37 是下一条设计路线（Work Receipts（工作收据）和 MRR 结算核心），目前处于设计和原型阶段，尚未在生产环境中运行。其论文的摘要见 Purple Paper 页面。
