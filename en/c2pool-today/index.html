c2pool today

The state of c2pool at release v0.2.12.16 (25 November 2026)

c2pool is a C++ reimplementation of p2pool, the decentralized mining pool, built for the V36 share format. It has no pool operator: miners run nodes that agree on a chain of shares, and every block a node finds pays the miners in that block’s own coinbase. The source is at github.com/frstrtr/c2pool.

Chains

c2pool builds one binary per parent chain (c2pool-<coin>). Several parent chains also merge-mine AuxPoW child chains in the same coinbase.

“Live” means that a public voidbind node runs that binary with no coin daemon on the serve path. It is not a claim of production maturity: only the Litecoin and Dash lines are in production use. DigiByte runs its Scrypt algorithm as a parent chain of its own; it is not a child chain of Litecoin.

Monero, in the project’s own words: “Experimental (v37 lane, Path B payouts; c2pool-v37-xmr, can run daemonless; not built by the release workflow): regtest, stagenet and testnet run a pool; mainnet runs only --follow-only and needs --i-understand-mainnet even for that.” Mainnet pool mode is disabled in code. (README, Supported chains)

No coin daemon

  • Litecoin and Dogecoin. c2pool embeds lightweight nodes for both chains. They sync headers over the coins’ own peer-to-peer networks, keep a UTXO set to compute fees, keep a mempool and build block templates themselves. No litecoind or dogecoind is needed.
  • Dash. c2pool-dash speaks the Dash peer-to-peer protocol itself and rebuilds the deterministic masternode list, LLMQ quorums, ChainLocks and the DIP-4 coinbase inside the node. It needs no dashd, no RPC credentials and no wallet access. Blocks built this way have been accepted on Dash mainnet. The Dash Core 24 rules are built in from v0.2.11.1, so a daemonless pool has no dashd to upgrade for that hard fork. A node can still be started with a dashd as a fallback.
  • Bitcoin, Bitcoin Cash, DigiByte and BIP-110 also run without a coin daemon on the public voidbind nodes.

The Litecoin share chain

  • Since 2026-11-13 00:00:00 UTC every share is a share version 3601 share: the V36 share format under share type 3601, fixed by a flag day in the release, not by a vote. It changed the merged-mining payout rule and lets a share carry several merged chains at once.
  • Only c2pool v0.2.12.1 and later are on this share chain. Python p2pool nodes are not.
  • The Python implementations p2pool-merged-v36 and p2pool-dash are no longer maintained. All updates, including security fixes, ship only in c2pool.
  • Payouts use PPLNS with exponential decay (half-life of a quarter of the 8,640-share window). One share is targeted every 15 seconds.

Public nodes

Public voidbind nodes with their dashboards: ltc.voidbind.com (Litecoin + Dogecoin), dash.voidbind.com, btc.voidbind.com, bch.voidbind.com, dgb.voidbind.com and bip110.voidbind.com. Each dashboard is a view of that node’s share chain; anyone running a node sees the same data from their own copy.

Download and verify

  • Packages per parent chain for Linux x86_64 (.tar.gz), Windows x86_64 (.zip or installer) and macOS (one universal package for Apple Silicon and Intel, macOS 26.0 or later) are on the releases page.
  • Each release carries a SHA256SUMS file and, from v0.2.7, a detached signature SHA256SUMS.asc. The signing key is published at github.com/frstrtr.gpg, fingerprint 99556F8DE6AD66057A1A10EC50AB1379285EFE76.
  • Known problems are listed in KNOWN_ISSUES.md.

What comes next

V37, the next design line (Work Receipts and the MRR settlement core), is at the design and prototype stage and is not run in production. Its paper is summarised on the Purple Paper page.
